## 결론 요약 (먼저 읽을 것) — slug 정화·whitespace·case-fold 크럭스

1. **`.toLowerCase()` 발산이 최고위험 (`sanitizeBranchSlug` / `slugifyForWorkspaceName`).** 두 정화 함수 모두 `.toLowerCase()` **후** ASCII 화이트리스트(`[^a-z0-9]`, `[^a-z0-9._-]`)로 비-ASCII를 버린다(`branch-name:37-38`, `workspace-name:25-33`). 함정: JS `"İ".toLowerCase()` → `"i̇"`(i + combining dot) → ASCII 클래스가 결합기호만 버리고 **`i` 를 살린다**. Rust `to_ascii_lowercase()` 는 `İ` 를 그대로 두므로 → 통째로 버려져 **`""`**. `ẞ`→`ß`, Kelvin `K`(U+212A)→`k`, `ﬁ` 리거처 등 동일. **→ 포트는 반드시 full `char::to_lowercase()`(scalar 단위 flat_map) 를 써야 함, `to_ascii_lowercase()` 금지.** (단 `isAutoGeneratedCreatureBranchName`·creature 집합은 코퍼스가 순수 ASCII라 `to_ascii_lowercase` 로 충분 — §1·§2.1 구분.)
2. **JS whitespace 집합 ≠ Rust `White_Space` — 그러나 이 클러스터는 자체 하드코딩 집합을 씀.** `workspace-name-text-scanner.ts:115-129` `isWorkspaceNameWhitespace` 는 코드포인트를 손으로 나열: `9-13, 32, 160, 5760, 8192-8202, 8232, 8233, 8239, 8287, 12288, 65279`. 이 집합은 **`suaegi-workref` 의 `js_ws::is_js_whitespace` 와 완전 동일**(U+FEFF 포함, U+0085 제외 — 확인함). `slugifyForWorkspaceName` 의 `.trim()`(`workspace-name:24`) 도 JS trim = 같은 집합. **→ 포트는 workref 의 `js_ws` 를 재사용(재-export)하거나 동일 집합을 복제.** 정규식 `/\s+/` 로 자르면 **안 됨** — 오라클이 `String.prototype.replace`/`split` 를 스파이해서 `/\s+/` 패턴 사용 0건임을 **명시적으로 검증**(`workspace-name.test.ts:31-41, 235-251`). 이건 성능 최적화가 아니라 **계약**이다: hand-rolled 스캐너 강제.
3. **Rust `regex` 크레이트는 lookahead `(?=…)` 미지원 — `workspace-name.ts` 아포스트로피 3함수가 전부 lookahead 사용.** `removeIntraWordApostrophes`(:14), `stripDanglingDisplayApostrophes`(:19-20) 는 `(?=[\p{L}\p{N}])` lookahead + `\p{L}\p{N}` **Unicode** 프로퍼티(여기선 Unicode ON 필요, ASCII-lock 아님!). **→ 정규식 불가, 손으로 스캔**(이전/다음 scalar 가 letter/number 인지 검사). §4 트랩표 T-APO.
4. **`\d`/`\b`/`\w` ASCII-lock — workref 의 C1 결정을 그대로 계승.** 이 클러스터에도 `\d`(숫자 매치)·`\b`(단어경계) 정규식이 다수(`isAutoGeneratedCreatureBranchName:27`, `leadingActionWord`/`collisionSuffixFromLeaf`, `getLinkedWorkItemTitleSubject`, `titleCaseWord`, `compactWorkItemTitle` 등). Rust `regex` 기본 `\d`=Unicode `Nd`, `\b`=Unicode → **`[0-9]`/`(?-u:\b)` 로 못박아야** JS ASCII 시맨틱과 일치. §4.
5. **UTF-16 인덱싱 함정 — `.charAt(0)`/`.slice(1)`/`.length`/`Number(rest)`.** `humanizeBranchSlug`(:89), `leadingActionWord`(:38), `titleCaseWord`(:122, :125), 스캐너의 `input.slice(tokenStart,tokenEnd)`·`charCodeAt`(code-unit 반복). 대부분 입력이 이미 ASCII 슬러그라 저위험이나, 스캐너는 원문(비-ASCII 프롬프트)을 code-unit 단위로 스캔 → astral 문자에서 발산 가능. `collisionSuffixFromLeaf` 의 `Number(rest)`(`display-name:53`)는 **선행 0 제거**(`fix-007`→`(7)`) — 포트도 파싱-재포맷 필요.
6. **의존 배선**: 새 leaf 크레이트 1개 → `suaegi-workref` 의존. 내부 순서: `marine-creatures`(무의존) → `branch-name-from-work`(marine 의존) → `display-name-from-work`(branch + workref); `workspace-name-text-scanner`(무의존) → `workspace-name`(scanner + workref). workref 소비 지점: `deriveWorkspaceDisplayName`(extract+format), `getWorkspaceIntentName`(format). §7.
7. **`MARINE_CREATURES` = 정확히 552 엔트리**, 순수 ASCII 단일 토큰(공백/하이픈/아포스트로피 없음, 중복 없음). 멤버십 인식(`isAutoGeneratedCreatureBranchName`)이 **정확한 전체 리스트**를 요구 → 552개 verbatim 복제 필수. §2.
8. **오라클 미커버 트랩(추가 핀 필요)**: `buildBranchNamePrompt`·`humanizeBranchSlug` 의 non-ASCII/astral, `sanitizeBranchSlug` 의 `İ`-style full-lowercase 발산, marine-creatures 멤버십의 552개 정확성(테스트 파일 없음), 스캐너의 code-unit vs scalar. §6 말미.

### 2.1 `isAutoGeneratedCreatureBranchName` (:20-29)
```
normalized = branchLeaf.trim().toLowerCase()      // normalizeName, :21
if (!normalized) return false                      // :22-24
base = normalized.replace(/-\d+$/, '')             // 후행 -숫자 1개 제거, :27
return CREATURE_NAMES_LOWER.has(base)              // :28
```
- **regex `/-\d+$/`** (플래그 없음): 문자열 **끝**의 `-` + 1개이상 숫자를 제거. `\d` = JS ASCII. **`Octopus-2`→`octopus`**, `Seahorse-17`→`seahorse`. **한 번만** 제거(`replace` 전역 아님) — `foo-2-3`→`foo-2`. **Rust: `[0-9]` 로 못박기** (`-٢`(아라비아 숫자)는 JS에서 stripping 안 됨 → 매치 실패 → 원형 유지). 앵커 `$` 필수.
- **case-fold**: 코퍼스가 ASCII이고 매치는 ASCII 집합 대상이라, 입력의 `.toLowerCase()` 를 `to_ascii_lowercase` 로 해도 **결과(bool) 불변** — full-lowercase 발산이 만드는 유일 차이는 비-creature 입력이고 그건 어차피 false. **→ 여기선 `to_ascii_lowercase` 안전**(단 verbatim 충실도 원하면 full). `.trim()` = JS trim(js_ws).
- 엣지: 빈/공백-only → false. `Nautilus`/`octopus` → true(대소문자 무관). `fix-auth-bug`·`my-feature` → false.

### 2.2 `sanitizeBranchSlug` (:35-45) — **최고위험 정화기**
```
words = raw.toLowerCase()                          // :37 full-Unicode lowercase
           .replace(/[^a-z0-9]+/g, '-')            // :38 비-ASCII영숫자 런 → '-'
           .split('-').filter(Boolean)             // :39
if (words.length === 0) return ''                  // :41-43
return words.slice(0, maxWords).join('-')          // :44 배열 slice(단어캡)
```
- **`.toLowerCase()` 발산 (T-LOWER, 결론 §1)**: `[^a-z0-9]` 는 순수 ASCII 클래스(regex 크레이트에서 유니코드 무관하게 리터럴 범위). 위험은 lowercase 단계. `İ`→JS `i̇`→`i` 생존 vs Rust `to_ascii_lowercase` → `İ` 유지 → strip → 소실. **포트는 full `to_lowercase()` 필수.**
- **단어 캡**: `words.slice(0, maxWords)` 은 **배열** slice(단어 개수), 문자열 slice 아님 → UTF-16 무관, 안전. 기본 `maxWords=4`(`MAX_BRANCH_NAME_WORDS`).
- 엣지: `'Fix the auth bug'`→`fix-the-auth-bug`; `'add dark mode toggle to settings page'`→`add-dark-mode-toggle`(4캡); `maxWords=2`→`add-dark`; `'"feat/login_flow!!"'`→`feat-login-flow`; `'   !!! ___ '`·`''`→`''`.

### 2.3 `stripConfiguredBranchPrefix` (:58-77)
```

                   .replace(/[^a-z0-9]+/g, '-')
                   .replace(/^-+|-+$/g, '')          // :65-69

```
- `prefix` 를 slug 와 **동일 정규화**(T-LOWER 동일 적용) 후, `slug` 가 `prefixSlug-` 로 시작하면 그 접두(+하이픈)만 제거. `slug.slice(prefixSlug.length+1)`: `prefixSlug` 는 `[a-z0-9-]`(ASCII)라 UTF-16 code-unit = byte = char → **Rust byte-slice 안전**.
- 엣지: `('tmchow-worktree-…','tmchow')`→접두제거; `('my-team-add-logout','my-team')`→`add-logout`; `('jane-doe-fix-auth','Jane.Doe')`→`fix-auth`(prefix 정규화로 `jane-doe`); `('add-logout-button','tmchow')`→불변(접두 아님); `('tmchow','tmchow')`→`''`(=slug 스킵 신호); prefix `null`/`undefined`/`''`→불변.

### 2.4 `humanizeBranchSlug` (:84-90)
```

return joined.charAt(0).toUpperCase() + joined.slice(1)  // :89 첫글자 대문자화
```

### 3.2 `collisionSuffixFromLeaf` (:45-54)
```

    || !resolvedLeaf.startsWith(`${baseSlug}-`)) return null   // :49
rest = resolvedLeaf.slice(baseSlug.length + 1)                 // :52
return /^\d+$/.test(rest) ? Number(rest) : null                // :53
```
- **`Number(rest)` = 이 클러스터 유일 숫자 파싱**. `rest` 가 전부 숫자일 때만. **선행 0 제거**: `resolvedLeaf='fix-007'`, `baseSlug='fix'` → rest `'007'` → `Number` → `7` → 표시 `(7)`. **Rust: `rest.parse::<u64/…>()` 후 재포맷**(문자열 그대로 쓰면 `(007)` 틀림). 큰 수 오버플로우 이론상 가능 — JS `Number` f64. `\d` ASCII lock. `.slice(baseSlug.length+1)` baseSlug=ASCII slug → 안전.

### 3.3 `deriveWorkspaceDisplayName` (:63-76)

### 4.1 아포스트로피 정규화 (T-APO — **lookahead, Rust regex 불가**)

### 4.2 `slugifyForWorkspaceName` (:23-39) — **두 번째 정화기**

## 8. Codex 교차검증용 미해결 질문 (consolidated)

- **Q1 — 정규식 vs 손코딩 + `\w`/`\s`/`\d`/`\b` Unicode-vs-ASCII 결정.** workref C1 을 계승: 이 클러스터의 `\d`(≥7곳: `isAutoGenerated…:27`, `leadingActionWord`/`collisionSuffix`, `getLinkedWorkItemTitleSubject`, `titleCaseWord`, `compactWorkItemTitle` 동적), `\b`(`getLinkedWorkItemTitleSubject:66`, `compactWorkItemTitle:152`) 를 **`[0-9]`/`(?-u:\b)`** 로 못박기. `ACTION_LABELS`/동적 regex 의 부정 ASCII 클래스 `[^a-z0-9_-]`·`[^:]` 에 `(?i)` 가 Unicode 케이스폴딩을 켜지 않도록 **`(?i-u:…)`** 로 잠글지. `[^a-z0-9._-]`(slugify)/`[^a-z0-9]`(branch) 는 리터럴 ASCII 범위라 Unicode 무관 — 확인만.
- **Q2 — T-APO: lookahead 3함수(`removeIntraWordApostrophes`, `stripDanglingDisplayApostrophes`)를 어떻게?** Rust `regex` lookahead 미지원. (a) 손코딩 scalar 스캔(`\p{L}\p{N}` ≈ `char::is_alphabetic()||is_numeric()`) — `\p{N}` vs `is_numeric`(Nd/Nl/No) 경계 일치 검증 필요; (b) `fancy-regex` 도입. 권고 (a). 경계사례: `\p{L}` 는 Lu/Ll/Lt/Lm/Lo — `is_alphabetic` 과 일치하는가?
- **Q3 — case-fold/whitespace 술어.** `sanitizeBranchSlug`/`slugifyForWorkspaceName`/`titleCaseWord` 의 `.toLowerCase()`/`.toUpperCase()` 를 **full `to_lowercase()`/`to_uppercase()`(scalar flat_map)** 로 통일(§1 발산). 단 creature 멤버십·아크로님 등 ASCII-보장 지점은 `to_ascii_*` 로 최적화 가능한지 개별 판정. whitespace 는 스캐너 하드코딩 집합(=workref js_ws) — `/\s+/` 정규식 금지(오라클 스파이 계약).
- **Q4 — UTF-16 word-count/slice.** `humanizeBranchSlug`/`leadingActionWord`/`titleCaseWord` 의 `charAt(0)`/`slice(1)`/`.length===1`, 스캐너의 `input.slice(tokenStart,tokenEnd)`·code-unit 반복, `compactWorkItemTitle` 의 `[^:]{1,32}`, `collisionSuffix` 의 `Number(rest)`(선행0 제거). 실입력이 ASCII 슬러그인 지점은 scalar 로 근사 가능하나, **스캐너는 원문(비-ASCII 프롬프트)을 code-unit 로 스캔** → astral 정확 재현 필요 여부 결정(§6.4 미커버).
- **Q5 — MARINE_CREATURES 정확-리스트 요구.** 552개 verbatim 복제 확정(중복 0, 순수 ASCII). 인식(`isAutoGeneratedCreatureBranchName`)이 전체 집합 정확성에 의존 — 테스트 없음 → count(552)+샘플 멤버십 회귀 핀을 새로 추가할지, 아니면 데이터-동등성만 별도 검증할지.
- **Q6 — 크레이트/모듈 레이아웃.** 새 leaf 크레이트 1개가 `suaegi-workref` 에 의존(§7). 은닉 5번째 모듈 `workspace-name-text-scanner` 를 별도 모듈로 포함. workref 의 `js_ws` 를 `pub` 재-export 해서 공유할지, 새 크레이트에 whitespace 집합을 복제할지(DRY vs 크레이트 경계). `humanizeBranchSlug` 는 새 크레이트 내부 공유(branch_name → display_name).
